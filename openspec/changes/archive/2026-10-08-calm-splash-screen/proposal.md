# Proposal

## Why

Whenever nothing is presenting (SteamVR still starting, the driver connected but not yet drawing, a GPU mismatch), the presenter fills the glasses with a stereo test pattern: a dark red left eye, a dark blue right eye, bright white borders and a centre line, and a green square sliding back and forth with a different offset in each eye. The wearer reported that it makes them nauseous. It was built to prove that each eye gets its own half in full SBS, which has been verified (`docs/findings.md`, "Full SBS stereo"), but it is also the first thing every session shows, for several seconds at every start.

Likely causes, not yet isolated (the wearer's report is the only measurement):
- Different colours per eye cannot be fused (binocular rivalry).
- A moving object with a disparity offset gives motion and depth cues with nothing else to rest on.
- Full-brightness edges at the border of each eye's view and a hard line down the middle.

## What We Know and What We Assume

Verified:
- The red/blue pattern is the nausea source the wearer is reacting to (their report; the pattern is the only thing shown before SteamVR presents).
- Per-eye stereo in full SBS works (shown with this very pattern), so the pattern is no longer needed as the default.

Assumed, with the experiment that settles each:

| Assumption | Experiment |
|---|---|
| Identical, static, dark, low-contrast content in both eyes is comfortable | The wearer looks at the new splash on the Deck for a few minutes and compares it with the old pattern; the same wearer is the judge |
| A fade-in from black over about one second removes the jolt of the screen lighting up | Same session, with and without the fade (fade length is a constant that can be tuned) |
| Zero disparity (same pixels in both halves) reads as a flat picture at the screen's depth without strain | Same session; if it feels flat or too close, try a small uncrossed offset |

## What Changes

- Replace the default "nothing is presenting" picture with a calm splash: very dark neutral background, a small centred mark and the text "Waiting for SteamVR", identical in the left and right halves, static, with no bright border or centre line.
- Fade the splash in from black over about a second whenever it starts showing (window first shown, or after SteamVR stops presenting), so it never flashes on.
- The splash image is pre-rendered (generated by a script, committed as raw pixel data the presenter embeds), the same way the shaders are precompiled and committed, so the presenter gains no runtime image or font dependency.
- Move the old red/blue pattern behind a new opt-in `--test-pattern` flag, alongside `--test-grid`. It is unchanged in appearance. Like `--test-grid` it shows the window without waiting for a driver and is drawn even while SteamVR is presenting.
- Update `presenter/README.md`, the presenter's header comment and usage line, and `docs/handoff.md`.
- Coordination: the in-flight `support-other-gpus` change says to "show the test pattern" on a GPU mismatch. Once this change lands that means the splash; that change's wording is updated when it is next touched, and this change does not edit it.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `presenter-display`: the requirement "Test pattern when nothing is presenting" is replaced by a splash requirement (calm, identical in both eyes, fades in); a new requirement makes the red/blue stereo test pattern available only with `--test-pattern`.

## Impact

- `presenter/src/main.rs`: `record_pattern` becomes the opt-in test pattern; a new splash draw path (texture upload, blit into both halves, fade factor); argument parsing and the standalone-window rule for `--test-pattern`; header comment and usage line.
- New: a splash generator script (like `packaging/make_icon.py`) and its committed output under `presenter/`.
- `presenter/README.md`, `docs/handoff.md`: wording.
- `openspec/specs/presenter-display/spec.md`: modified at archive.
- Packaging and the driver are untouched. Nothing here depends on the Deck's GPU; the splash uses a plain Vulkan image upload and blit.

## Non-goals

- Changing anything about what SteamVR frames look like, reprojection, or the per-eye render size.
- A branded or animated loading screen, a progress indicator, or showing connection status text beyond "Waiting for SteamVR".
- Localisation of the splash text.
- Showing a different splash for different reasons (no driver, GPU mismatch, glasses absent). One picture for all of them.
- Proving why the old pattern causes nausea. Only whether the new one is comfortable is checked.
