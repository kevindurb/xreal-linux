# Design

## Context

`record_pattern` in `presenter/src/main.rs` is the only "nothing is presenting" picture. `draw` picks it when `prepare_eyes` returns `None` and `--test-grid` is not drawing, and it is built entirely from `vkCmdClearAttachments` rectangles inside a dynamic-rendering pass, with no texture, shader or font. The window exists only while the driver is connected and the glasses' output is up in full SBS (or with `standalone` flags such as `--test-grid` and `--sim-pose`), so the splash is mostly seen between the driver connecting and SteamVR's first frame. The swapchain is the glasses' 3840x1080 SBS mode, and `record_blit` already writes it with transfer operations, so it is created with `TRANSFER_DST` usage. See proposal.md for motivation.

## Goals / Non-Goals

**Goals:**
- A calm, correct-by-construction splash: identical halves, static, dark, low contrast, text included, fading in.
- The old pattern kept exactly as it is, behind `--test-pattern`.
- No new runtime dependency, no new shader, no change to the SteamVR path.

**Non-Goals:**
- A general 2D drawing or text layer in the presenter.
- Making the splash react to why nothing is presenting.

## Decisions

**1. A small pre-rendered patch, not a full-screen image.** The splash is a flat dark background with one small block (a mark and the text) in the middle. Only the block is stored: a single-channel coverage image of about 640x160 (about 100 KB), committed as raw bytes and embedded with `include_bytes!`, the way the compiled shaders are committed. The background is a clear. Alternatives: a full 1920x1080 image per eye (2 MB for 1 byte per pixel, 8 MB as RGBA, mostly one colour); rendering text at runtime (needs a font library, which would break the "only needs Vulkan, Wayland and xkbcommon" property recorded in `presenter/README.md`).

**2. Generated by a standard-library Python script with an embedded bitmap font.** Like `packaging/make_icon.py`, the generator uses no imaging library, so anyone can regenerate the asset. It draws two lens shapes (the project's icon motif) above the line "Waiting for SteamVR" in a 5x7 bitmap font scaled up, and can also write a PNG for looking at it. Alternative: render with a system font via Pillow or fontconfig, which is nicer looking but not reproducible across machines. If the blocky text looks bad on the glasses, the script can be changed without touching the presenter.

**3. Fade with a buffer copy and a clear, not a shader.** Each splash frame is written with transfer commands only: `vkCmdClearColorImage` of the whole swapchain image to the background level, then `vkCmdCopyBufferToImage` of the patch into the middle of the left half and the same bytes into the middle of the right half (so the halves are identical by construction, with zero disparity). During the fade the patch is scaled by the fade level on the CPU into a small host-visible staging buffer (about 100 KB, one write per frame for about 60 frames), and the clear level is scaled the same way; once the fade is done the buffer is written once and reused. Alternatives: a blended full-screen quad (needs a new pipeline and a shader compiled and committed), or re-using the warp pipeline (only exists with `--reproject`). The fade curve is smoothstep over about 1 s; level 0 on the first frame, so the first frame is black.

**4. The fade restarts when the splash starts to show.** The presenter keeps the time the splash began; a frame that presents SteamVR's eyes clears it. So the fade plays when the window first shows and again if SteamVR stops presenting and the splash returns.

**5. Neutral grey, no tint.** The patch and background are grey levels (equal R, G and B). The swapchain format is whichever the surface offers (a BGRA or RGBA unorm or sRGB format), and a copy writes the bytes unchanged, so a coloured splash would swap red and blue on one of them. Grey avoids that and also removes any chance of a colour difference between eyes. Levels are constants near the top of the new `presenter/src/splash.rs`, easy to tune after the wearer looks at it.

**6. `--test-pattern` is the old code, selected by a flag.** `record_pattern` keeps its drawing code; `draw` calls it first when the flag is set (before the eye images and the test grid, so the pattern wins over `--test-grid`), and the window is shown without a driver, as `--test-grid` does. Without the flag the pattern is unreachable. Alternative: delete the pattern; rejected because the per-eye check is still useful on new hardware (see `support-other-gpus`) and costs nothing to keep.

**7. Pure logic in `splash.rs`.** The fade level as a function of elapsed time, the scaling of a coverage patch into bytes, and the placement offsets are plain functions with unit tests, in the style of `warp.rs`. The Vulkan recording stays in `main.rs`.

**Dependence on hardware.** Nothing here is specific to the Steam Deck: only core Vulkan transfer commands and a host-visible buffer are used, and the swapchain's `TRANSFER_DST` usage is already relied on by `record_blit`. It does not touch the pressure-vessel boundary, SteamVR settings or the glasses' menu settings. The glasses must be in full SBS for the two halves to go to separate eyes, as before.

## Risks / Trade-offs

- [The splash is still uncomfortable (brightness of the text, flat zero-disparity picture)] → Levels, fade length and an optional small disparity are constants; the wearer judges on the Deck, and the old pattern is not the fallback, so tune the splash instead.
- [A stale splash remains visible under SteamVR's frame] → The SteamVR path is `record_blit`/`record_warp`, which cover the whole image; verified with a frame dump after takeover.
- [Block-letter text looks crude] → Regenerate with a different font or scale; the presenter only sees the raw patch and its size.
- [Raw patch size and the Rust constants drift apart] → The generator writes the width and height beside the data and a unit test checks the byte count against them.
- [`support-other-gpus` still says "test pattern" for a GPU mismatch] → After this change that picture is the splash; the wording is fixed when that change next changes. Recorded in tasks as a check, not edited here.

## Open Questions

- Whether a small uncrossed disparity (the splash a little farther away) is more comfortable than a flat picture at the screen's depth. Settled by the wearer's check; it changes constants only.
